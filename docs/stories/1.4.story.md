# Story 1.4 — API de Configuração e Branding do Tenant

## Descrição

**Como** frontend do app de delivery,
**quero** buscar a configuração de branding do tenant atual (logo, cor, nome, horários) sem autenticação,
**para que** a home page de qualquer restaurante carregue com sua identidade visual correta desde o primeiro render.

---

## Contexto Técnico

- **Endpoint:** `GET /api/tenant/config`
- **Auth:** Pública (sem autenticação) — o tenant é resolvido pelo subdomínio
- **Cache:** `Cache-Control: public, s-maxage=300` (5 minutos na CDN Vercel/Cloudflare)
- **CSS vars:** O layout do tenant injeta os valores como `style` no `<html>` para Tailwind v4 consumir
- **Arquitetura:** `docs/architecture/fullstack-architecture.md` (Seções 3 e 9)
- **Schema:** Tabela `tenants` — campos `logo_url`, `banner_url`, `cor_primaria`, `cor_primaria_texto`, `horarios`, `config`

---

## Acceptance Criteria

### AC1 — Endpoint de Configuração
- [ ] `GET /api/tenant/config` retorna 200 com body:
```json
{
  "id": "uuid",
  "slug": "restaurante-a",
  "nome": "Restaurante A",
  "logo_url": "https://cdn.r2.../logo.png",
  "banner_url": "https://cdn.r2.../banner.jpg",
  "cor_primaria": "#FF6B35",
  "cor_primaria_texto": "#FFFFFF",
  "horarios": { "segunda": { "aberto": true, "inicio": "11:00", "fim": "22:00" }, ... },
  "status": "open" | "closed",
  "frete_base": 5.00,
  "frete_gratis_acima": 50.00,
  "tempo_preparo_min": 30
}
```
- [ ] `tenant_id` extraído do `x-tenant-id` header — **nunca exposto no response**
- [ ] Tenant inexistente → 404
- [ ] Tenant com `ativo = false` → `{ "status": "closed", "message": "Restaurante temporariamente indisponível" }`

### AC2 — Campo `status` (aberto/fechado)
- [ ] `status` calculado server-side com base em `horarios` JSONB e horário atual (timezone `America/Sao_Paulo`)
- [ ] Retorna `"open"` se dentro do horário de funcionamento do dia atual
- [ ] Retorna `"closed"` se fora do horário, dia fechado, ou tenant inativo

### AC3 — Cache
- [ ] Header `Cache-Control: public, s-maxage=300, stale-while-revalidate=60` no response
- [ ] Resposta idêntica para múltiplas requisições no mesmo tenant dentro do TTL (sem DB hit)
- [ ] `ETag` gerado a partir do `atualizado_em` do tenant (para invalidação precisa)

### AC4 — Performance
- [ ] Tempo de resposta < 100ms para tenant em cache
- [ ] Sem N+1 queries — single `SELECT` na tabela `tenants`
- [ ] Não retornar campos sensíveis: `pagamento_config`, `auth_user_id`, dados de clientes

### AC5 — Layout do Tenant (Server Component)
- [ ] `app/(tenant)/layout.tsx` chama `GET /api/tenant/config` via Server Component
- [ ] Injeta CSS vars no `<html>`:
```tsx
<html style={{
  '--color-primary': config.cor_primaria,
  '--color-primary-fg': config.cor_primaria_texto,
}}>
```
- [ ] Tenant fechado (`status: "closed"`) exibe banner de "Fechado no momento" na home
- [ ] Logo e nome do tenant no `<title>` e meta tags OG (SEO)

### AC6 — Testes
- [ ] Teste: endpoint retorna config correta para tenant ativo
- [ ] Teste: `status: "closed"` fora do horário de funcionamento
- [ ] Teste: tenant-A e tenant-B retornam configs distintas
- [ ] Teste: campos sensíveis (`pagamento_config`) ausentes no response
- [ ] Teste de cache: segundo request retorna header `Cache-Control` correto
