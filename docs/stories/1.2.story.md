# Story 1.2 — Roteamento Multi-Tenant por Subdomínio

## Descrição

**Como** plataforma multi-tenant,
**quero** que cada requisição identifique automaticamente qual tenant está sendo acessado pelo subdomínio ou domínio customizado,
**para que** todos os componentes da aplicação recebam o `tenant_id` correto sem precisar de configuração manual por requisição.

---

## Contexto Técnico

- **Arquivo:** `middleware.ts` na raiz do Next.js (edge runtime)
- **Estratégia:** Extração do hostname → lookup em `tenants` → injeção de `x-tenant-id` no header
- **Cache:** 60 segundos via Vercel Edge KV ou `Cache-Control`
- **Subdomínio padrão:** `<slug>.plataforma.com`
- **Domínio customizado:** `delivery.restaurante.com.br` via CNAME
- **Arquitetura:** `docs/architecture/fullstack-architecture.md` (Seção 3)
- **Schema:** `tenants.slug` e `tenants.custom_domain` (Story 1.1 pré-requisito)
- **Runtime:** Edge (não Node.js) — usar apenas APIs compatíveis com edge

---

## Acceptance Criteria

### AC1 — Resolução por Subdomínio
- [ ] `restaurante-a.plataforma.com` → resolve `tenant_id` do restaurante-a
- [ ] `restaurante-b.plataforma.com` → resolve `tenant_id` do restaurante-b (diferente do anterior)
- [ ] Slug inválido (tenant não encontrado) → retorna 404 com página de erro amigável (não crash)
- [ ] Tenant com `ativo = false` → retorna 503 com mensagem "Restaurante temporariamente indisponível"

### AC2 — Resolução por Domínio Customizado
- [ ] `delivery.restaurante.com.br` → busca por `custom_domain` na tabela `tenants` → resolve `tenant_id`
- [ ] Domínio customizado não cadastrado → retorna 404

### AC3 — Injeção de Context
- [ ] `x-tenant-id` injetado em `request.headers` para todas as rotas (exceto `/api/webhooks/*`)
- [ ] Server Components podem ler `tenant_id` via `headers().get('x-tenant-id')`
- [ ] API Routes podem ler `tenant_id` via `request.headers.get('x-tenant-id')`
- [ ] `tenant_id` ausente em rotas protegidas → retorna 401

### AC4 — Supabase Context
- [ ] Antes de qualquer query Supabase no servidor, executar: `SET LOCAL app.current_tenant_id = '<tenant_id>'`
- [ ] Helper `getSupabaseWithTenant(tenantId)` disponível em `lib/supabase/server.ts`
- [ ] RLS valida isolamento automaticamente em todas as queries que usam esse helper

### AC5 — Cache de Resolução
- [ ] Resultado da resolução de tenant cacheado por 60s (evita DB lookup em toda requisição)
- [ ] Cache invalidado quando `tenants.ativo` muda (via Supabase webhook ou revalidação manual)

### AC6 — Rotas Excluídas do Tenant Context
- [ ] `/api/webhooks/*` — sem tenant context (webhooks do Pagar.me)
- [ ] `/_next/*` — assets do Next.js, sem processamento
- [ ] `/favicon.ico` e arquivos estáticos

### AC7 — Testes
- [ ] Teste unitário: `resolveTenant('restaurante-a.plataforma.com')` retorna `{ id, slug, nome }`
- [ ] Teste unitário: `resolveTenant('dominio-invalido.com')` retorna `null`
- [ ] Teste de integração: request com subdomínio válido recebe header `x-tenant-id` correto
- [ ] Teste de cross-tenant: `x-tenant-id` do restaurante-a não resolve dados do restaurante-b via RLS

|-------|--------------|-----------|
| Edge runtime não suporta biblioteca usada | Média | Verificar compatibilidade com edge antes de usar qualquer lib |
