# Story 2.1 — Seed Data do Catálogo

## Descrição

**Como** desenvolvedor,
**quero** ter dados realistas de categorias e produtos nos dois tenants de teste (restaurante-a e restaurante-b),
**para que** as Stories 2.2 (APIs) e 2.3 (UI) possam ser desenvolvidas e testadas com dados reais.

---

## Contexto Técnico

- **Tabelas existentes:** `product_categories`, `products` (Migration 003)
- **RLS:** Políticas de isolamento por tenant já ativas (Migration 005)
- **Customizações:** Campo `customizacoes` JSONB no `products` — formato de array de grupos
- **Tenants de teste:** `restaurante-a` e `restaurante-b` já existem no DB

---

## Acceptance Criteria

### AC1 — Seed de Restaurante A (pizzaria)
- [ ] 3 categorias criadas: "Pizzas", "Bebidas", "Sobremesas"
- [ ] Mínimo 2 produtos por categoria (6 produtos total)
- [ ] Pelo menos 1 produto com customizações (tamanho + borda)
- [ ] Todos com `disponivel = true` e `ativo = true`

### AC2 — Seed de Restaurante B (hamburgueria)
- [ ] 3 categorias criadas: "Lanches", "Acompanhamentos", "Bebidas"
- [ ] Mínimo 2 produtos por categoria (6 produtos total)
- [ ] Pelo menos 1 produto com customizações (ponto da carne + adicionais)
- [ ] Todos com `disponivel = true` e `ativo = true`

### AC3 — Isolamento RLS
- [ ] Query com tenant_id de restaurante-a NÃO retorna produtos de restaurante-b
- [ ] Query com tenant_id de restaurante-b NÃO retorna produtos de restaurante-a

### AC4 — Formato de Customizações
- [ ] Campo `customizacoes` segue o schema:
```json
[
  {
    "nome": "Tamanho",
    "tipo": "choice",
    "obrigatorio": true,
    "opcoes": [
      { "nome": "Pequena", "preco_adicional": 0 },
      { "nome": "Grande", "preco_adicional": 15 }
    ]
  }
]
```
